# Screenshot editor v2: roadmap

Three architects each wrote a v2 plan independently, from a different angle. They all started from the two editor
reviews ([01-screenshot-editor.md](01-screenshot-editor.md)) and from the code itself. The full plans, with code
sketches in Rust and TypeScript:

- [editor-plans/incremental.md](editor-plans/incremental.md): **quick wins first**, no rewrite, about 28 dev-days
  in six shippable releases.
- [editor-plans/architecture.md](editor-plans/architecture.md): **foundation first**. A typed sidecar document, a
  crash-safe commit and one rasteriser. About 29 dev-days.
- [editor-plans/gamer.md](editor-plans/gamer.md): **gamer workflow first**. Hotkey to Discord in about a second,
  keyboard-first, editing from the in-game console, per-game redaction templates, HDR and 8K. About 40 dev-days.

## Where all three agree: do this first

Every plan opens with the same milestone, and the reasons are strong:

1. **Redaction you can trust.**
   - Replace the single box blur in `shot.rs` with three box passes whose radii are rounded *up*, so the file is
     never weaker than the CSS preview.
   - Add a solid **Redact** tool, which is the only truly irreversible option.
   - On a failed thumbnail rebuild, drop the old unredacted thumbnail.
   - Correct the "what you see is what lands in the file" hint.
2. **Saves that cannot lose or corrupt anything.**
   - Stage `base.png`, `shot.json` and the new picture under temporary names, swap the main PNG in first, and only
     then commit the sidecar files.
   - Hold a per-clip lock across `write_screenshot`, `file_clip` and `delete_clip`.
   - Re-read the clip's current path under the library lock just before writing.
3. **Saves tied to their picture.**
   - Keep the editor disabled until its edit state has loaded, and show load errors.
   - Check the shown clip's id after every `await`.
   - Freeze input and close/delete while a save runs.
   - Guard the ✕ close button against unsaved marks, as Escape already does.
4. **Cap PNG sizes** before allocating in `read_png` / `read_rgba`.

## Where they differ

| Question | Incremental | Architecture-first | Gamer-first |
|---|---|---|---|
| Renderer | Keep the hybrid and contain the drift (3-pass blur, feathered oval, parity tests) | ADR-1: one rasteriser (OffscreenCanvas in the WebView) for preview and export; Rust keeps files, watermark, clipboard and thumbnails | Keep the hybrid for now; the redaction core stays in Rust |
| Sidecar format | Add a `version` field | Typed `shot_doc.rs` v2 with TS types generated by ts-rs, migration and a downgrade shadow | Version it as part of the M0 redaction work |
| First big feature | Editor quick wins: redo, tool hotkeys, Shift-constrain, remembered styles, in-editor Copy | "Retire the duplicate, build on it": new tools land once, in the single renderer | Hotkey to Discord: "fit for Discord" export, one clipboard session (PNG + DIB + file), copy after capture |
| Later | 4K/8K performance (display-resolution canvases, binary IPC), sharing and export, more marks (line, highlighter, steps, spotlight) | Typed document, locks and safe commit (M1), then the renderer (M2) | Keyboard-first (M2), editing from the console (M3), per-game redaction templates (M4), HDR, multi-monitor and 8K (M5) |

## Recommended path (my synthesis)

1. **0.8.4 hotfix (3–4 days):** the shared first milestone above, items 1 and 4, using the incremental plan's
   sketch A (the 3-pass blur with a test that it is never weaker than the preview).
2. **Next release (about 1 week):** items 2 and 3. Use the incremental plan's sketches B and C, or the gamer plan's
   sketch 2, which is the same idea: one writer per shot, the file first, the continuation guarded. Adopt the
   architecture plan's per-clip lock and the version field now.
3. **Quick wins (about 1 week):** redo, tool hotkeys, Shift-constrain, remembered styles, Copy / Save & copy in the
   editor, and showing marks during crop. Add the vector tools that need no core change: line and double arrow,
   highlighter, numbered steps, spotlight, emoji.
4. **Sharing (about 1 week):** the gamer plan's M1. Export as PNG/JPEG/WebP with "fit under N MB", one clipboard
   session carrying PNG + DIB + file, and an optional copy after capture.
5. **Foundation before pixel tools:** the architecture plan's M1–M2 (typed v2 document, binary IPC, one rasteriser),
   before pixelate, magnifier, beautify or OCR-driven auto-redaction.
6. **Then** OCR "copy text" (`Windows.Media.Ocr`), the gamer plan's per-game redaction templates, and the
   accessibility pass.
